# 项目 Codex 指令

## 项目目标

- 使用引用的 `Stc8hBase` 基础库实现本项目，不复制或修改基础库代码。
- 目标硬件为 STC8H1K08 + CN5711，红外输入为 P3.2 / INT0。
- 固件需支持 NEC 红外协议和 repeat 码，尽量低功耗，并保留可开关的串口调试日志。
- 老 Keil 工程已归档到产品仓库 `legacy/lamp_keil/`，仅作为需求参考；旧实现不合理时按当前目标重新设计。

## 基础库边界

- 本项目只能修改当前项目文件，不能修改相邻目录中的 `Stc8hBase`。
- 遇到基础库 bug 或缺能力时，不要在本项目绕路打补丁。
- 确认属于基础库问题后，输出给用户的基础库修复提示词，包含背景、证据、影响、复现方式和为什么不应在应用层绕过。
- 只有在真实需求阻塞、可复现 bug、或职责明显属于基础库时，才要求基础库改动。

## 先评估再实现

- 新需求、bug 修复、优化都必须先整体评估，再给方案，再改代码。
- 不要参考旧会话的临时实验结论作为事实；需要重新用证据确认。
- 多种解释并存时要列出可能性、证据和验证方法，不要默默选择。
- 不清楚就停下来说明哪里不清楚，并提出最小验证步骤。

## 权威资料优先

- 涉及 STC8H1K08 外设、寄存器、低功耗、唤醒、UART、Timer、PWM 时，优先查 STC 官方资料或基础库文档，再对照代码。
- 涉及 NEC 红外协议时，优先查 Vishay、Renesas、SB-Projects 等权威或成熟资料，再对照时序和状态机。
- 涉及 CN5711 时，优先查芯片资料确认 PWM、使能、关断和低功耗要求。
- 不要凭感觉调协议时序、主频、串口误差、低功耗流程或外设配置。

## 红外实现原则

- INT0 中断里只做短路径捕获：读 Timer、记录间隔、喂解码状态机；不得串口输出或做复杂业务。
- 主循环读取红外事件并执行命令。
- NEC 典型时序需按权威资料核对：leader、bit0、bit1、repeat、repeat 周期和容差。
- repeat 只应复用最近一次有效的增亮/减亮命令，不应重复触发开关或定时。
- 命令映射按地址分表，避免同一 command 在不同 address 下语义混淆。

## 当前命令需求

- `addr=0x01` 保持老项目语义：
  - `0x11` 开关。
  - `0x22` 增亮。
  - `0x33` 减亮。
  - `0x51` 15 分钟定时。
  - `0x52` 60 分钟定时。
- `addr=0x00` 新增实测遥控语义：
  - `0x18` 增亮。
  - `0x52` 减亮。

## 调试和验证

- 串口调试日志必须可通过构建开关开启或关闭；完成后可关闭以降低 ROM 占用。
- 上电 boot 日志只能证明 UART 和启动路径可用，不能证明 INT0 或红外解码可用。
- 遥控无反应时，第一步应做最小 INT0 计数诊断，区分“中断未进入”和“进入后解码失败”。
- 若 `debug_ir` 或诊断固件可用，不能直接推断正式固件可用；需对比初始化顺序、中断向量、寄存器和业务模块副作用。
- 每次构建后要检查关键产物：ROM/RAM、启动串、中断向量、烧录文件时间戳。

## 烧录和串口

- 默认串口：`/dev/cu.usbserial-110`。
- 常用烧录命令：
  `/tmp/stcgal-venv/bin/python -m stcgal -P stc8g -p /dev/cu.usbserial-110 -b 38400 -t 6000 build/ir_lamp.ihx`
- 常用监视命令：
  `pio device monitor --port /dev/cu.usbserial-110 --baud 115200`
- 如果烧录出现 `Protocol error`，该次固件不可视为有效测试结果。
